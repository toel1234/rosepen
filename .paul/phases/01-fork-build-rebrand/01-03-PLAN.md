<objective>
## Goal
A Flatpak bundle of Rosepen builds locally, and CI builds and smoke-tests it on every push.

## Purpose
Linux-only target needs a distro-independent package, and CI protects the baseline as phases 2 to 6 change the code.

## Output
`packaging/flatpak/<APP_ID>.yml`, `.gitlab-ci.yml` (or GitHub Actions, per checkpoint), `docs/PACKAGING.md`.
</objective>

<acceptance_criteria>

## AC-1: Flatpak builds
```gherkin
Given flatpak-builder and the GNOME runtime installed
When flatpak-builder runs on the manifest
Then a bundle is produced that installs and launches
```

## AC-2: CI green
```gherkin
Given a push to main
When CI runs
Then configure, build, headless SVG-to-PNG smoke test and Flatpak build all pass
```

## AC-3: Name-driven packaging
```gherkin
Given branding.cmake changes APP_ID
When the manifest is regenerated by the helper script
Then the manifest uses the new ID without manual edits
```

<tasks>

<task type="checkpoint:decision" gate="blocking">
  <decision>Where does the repo and CI live?</decision>
  <context>Decides CI file format and runners; the fork has no remote yet.</context>
  <options>
    <option id="gitlab">
      <name>GitLab</name>
      <pros>Same host as upstream, easy upstream merge requests, built-in runners</pros>
      <cons>Needs a GitLab account and runner minutes</cons>
    </option>
    <option id="github">
      <name>GitHub</name>
      <pros>Wide reach, free Actions minutes for public repos</pros>
      <cons>Separate from upstream workflow</cons>
    </option>
    <option id="local">
      <name>Local only</name>
      <pros>No accounts</pros>
      <cons>No real CI, only a local build script</cons>
    </option>
  </options>
  <resume-signal>Select: gitlab, github or local</resume-signal>
</task>

<task type="auto">
  <name>Task 1: Flatpak manifest and local bundle</name>
  <files>packaging/flatpak/, scripts/gen-flatpak.sh, docs/PACKAGING.md</files>
  <action>
    Write manifest on org.gnome.Platform (version matching GTK4 need), building from local src via CMake.
    scripts/gen-flatpak.sh reads branding.cmake and fills app ID and command.
    Build with flatpak-builder --user --install and run the app. Missing runtime installs need user approval.
  </action>
  <verify>flatpak run $APP_ID --version</verify>
  <done>AC-1, AC-3 satisfied</done>
</task>

<task type="auto">
  <name>Task 2: CI pipeline</name>
  <files>.gitlab-ci.yml or .github/workflows/build.yml</files>
  <action>
    Per checkpoint choice (local: scripts/ci-local.sh doing the same steps).
    Stages: deps, configure+build (ccache), smoke test (headless PNG export), flatpak build.
    Cache build dir; fail on warnings only if upstream baseline is clean.
  </action>
  <verify>Push or run locally; all stages pass</verify>
  <done>AC-2 satisfied</done>
</task>

</tasks>
