<objective>
## Goal
Build produces binary `rosepen` with its own app ID, name, desktop file and icons. All branding lives in one place so the later final rename is a one-file change.

## Purpose
Fork must not ship as "Inkscape" (trademark) or with any Corel branding. Name is provisional, so rename cost must stay near zero.

## Output
`src/branding.cmake` (single source of names), patched build and strings, placeholder original icons, `docs/RENAME.md`.
</objective>

<acceptance_criteria>

## AC-1: Single-point naming
```gherkin
Given src/branding.cmake defining APP_NAME, APP_BINARY, APP_ID, APP_DOMAIN
When APP_NAME is changed and the project reconfigured
Then binary name, window title, About dialog, desktop file and metainfo all follow it
```

## AC-2: Renamed build
```gherkin
Given the rebranded tree
When built and run
Then build/bin/rosepen exists, --version reports Rosepen plus the upstream version it is based on, and the window title reads Rosepen
```

## AC-3: No foreign marks
```gherkin
Given the whole source tree
When grepping user-visible strings, desktop/metainfo files and icons
Then no "CorelDRAW"/"Corel" appears, Inkscape appears only in licence, credits and "based on Inkscape" notices, and icons are original placeholders
```

## AC-4: Config isolation
```gherkin
Given an existing Inkscape install with user config
When Rosepen starts
Then it uses its own config and data dirs (~/.config/rosepen) and does not touch ~/.config/inkscape
```
