# 05-01 Manual UAT — PowerClip: place inside frame, edit contents in place, extract

Status: **OWED** (not run). The PowerClip model, actions, menus, key and the
headless behaviour (clipping, absolute placement, transform-follow, live
container clip, duplicates, extract, add-to-frame, master pages, refusal) are
locked by the gtest (`test_powerclip`, 17 cases) and the 8-scenario CLI corpus
(`cli_powerclip-*`), which are green. The interactive checks below need a
deliberate GUI session.

Environment note: `DISPLAY=:0` / `WAYLAND_DISPLAY=wayland-0` exist on the host,
but they belong to the live GNOME session and were not intruded on. `Xvfb` /
`xvfb-run` are absent, so no isolated display was available.

Draw the practice shapes on a fresh document: an ellipse (the frame) and a
photo-like group or rect clearly larger than the ellipse.

## Checklist

1. Place Inside Frame, three entry points
   - Select the content, then Shift-click the ellipse LAST, then run
     Object ▸ PowerClip ▸ Place Inside Frame.
   - The content is clipped to the ellipse and stays exactly where it was; one
     object (the PowerClip frame) is selected afterwards.
   - Repeat once via the right-click ▸ Place Inside _Frame item and once via
     Ctrl+Alt+P. Same result every time.
   - One Ctrl+Z after each placement restores the unplaced state completely
     (contents back on the layer, no frame group, no clipPath in the XML
     editor).
   - Entry point observed working: menu / context / key: ____________
   - `[ ]` pass `[ ]` fail

2. Selection model: the frame is one object
   - A single click on the PowerClip selects the whole frame (container +
     contents move together).
   - With the Select tool: move, scale, rotate and skew the frame. The
     contents follow every transform and stay clipped.
   - Ctrl+D, then move the copy: the copy is clipped correctly and the
     original is untouched.
   - `[ ]` pass `[ ]` fail

3. Edit Contents with dimming
   - With the PowerClip selected: Object ▸ PowerClip ▸ Edit Contents (and once
     via the right-click ▸ _Edit PowerClip Contents item).
   - Everything outside the contents is dimmed (upstream TranslucencyGroups,
     default pref "When in Groups"). With Preferences ▸ Behavior ▸
     translucency "Never" there is NO dimming (upstream setting respected).
   - The contents are selectable and editable in place; they stay CLIPPED
     while editing (known difference from CorelDRAW, which shows them
     unclipped during edit).
   - Finish Editing via the Object menu, the right-click menu or Exit Group:
     the view returns, the frame is selected and the dimming is gone.
   - Pref setting observed: ____________
   - `[ ]` pass `[ ]` fail

4. Double-click behaviour (upstream, recorded)
   - Double-click on a PowerClip enters the FRAME group (upstream Select-tool
     behaviour, unchanged by this plan).
   - A second double-click on the contents enters the contents group. There is
     no Corel-style single-step entry; this is the recorded behaviour.
   - `[ ]` pass `[ ]` fail

5. Live container clip + duplicate repair
   - Enter the frame (double-click), reshape the container with the Node tool
     (Ctrl+click into the frame): the clip follows the reshape live.
   - Ctrl+D the whole PowerClip, reshape the COPY's container, then run Edit
     Contents on the copy and Finish Editing once: the copy's clip follows its
     OWN container (normalize repair); exactly one "Repair PowerClip" undo
     step appears; the original is unchanged.
   - Reshape observed on the copy after Edit+Finish: ____________
   - `[ ]` pass `[ ]` fail
   - KNOWN DIVERGENCE (05-01 finding, do not count as a failure): moving the
     container SHAPE ALONE with the Select tool (inside the frame group) is
     anti-followed by upstream clone compensation (SPUse::move_compensate), so
     the clip stays behind and the container/clip diverge until Edit/Finish
     (normalize treats a transformed clip <use> as stale and re-creates it:
     one "Repair PowerClip" undo step realigns the clip; review gate fix).
     Moving or reshaping the whole PowerClip, node-editing the container and
     any non-translation reshape are unaffected. Observed: ____________

6. Extract Contents

     once via the right-click ▸ E_xtract Contents item).
   - The contents come out at their current visual position and are selected;
     the container is a plain object again (no role attribute in the XML
     editor, no clipPath left in defs).
   - One Ctrl+Z restores the PowerClip exactly.
   - `[ ]` pass `[ ]` fail
