<objective>
Give Rosepen CorelDRAW's flagship container feature, PowerClip. The user selects one or more objects, then the frame object (any shape, text or group) last, and runs Object ▸ PowerClip ▸ Place Inside Frame. The contents move inside the frame and are clipped to its shape. They keep their position on the page at placement time and from then on move, scale, rotate, duplicate and render with the frame as one object. Edit Contents enters the frame (everything else is dimmed), the user edits the contents in place, and Finish Editing returns to the page. Extract Contents takes them out again at their current visual position and gives back the plain container. Every document-changing operation is exactly one undo step. A PowerClip inside a master layer (03-02) renders on every page.

Purpose: Phase 5 adds the Corel tools. Upstream Inkscape (pinned 3d6e954a) already has every low-level part. SVG clip paths are first-class (`SPClipPath`, `clip-path` on any item, rendered per display key). `ObjectSet::setClipGroup` (selection-chemistry.cpp:3552-3643) proves that a clipPath whose only child is an `svg:use` of a visible in-document object works live. Entering a group (`LayerManager::setCurrentLayer`) already exists, and the desktop already dims everything outside an entered group (`TranslucencyGroups`). What upstream lacks is the Corel object: a frame that owns its container and its contents, keeps them aligned, and offers place / edit / finish / extract as commands. This plan adds that as one Gtk-free document model plus thin actions. It writes NO renderer, display, tool or selection-chemistry code.

Output: a gtest-locked `PowerClip` document model, five `app.object-powerclip-*` actions (CLI-verifiable; edit/finish need a desktop), GUI entry points (context menu, Corel Object menu, a key in the Rosepen key profile), a headless corpus that proves structure and rendered pixels (including transform-follow, duplicate, extract and master pages) and a manual UAT for the interactive edit-in-place flow.
</objective>

SVG `use` semantics: the referenced element is drawn with its OWN transform attribute in the use's coordinate system, and the referenced element's ancestors are ignored. - Transform writing (sp-item.cpp:1733-1744): `doWriteTransform` embeds the transform (`set_transform`) only when the item has NO clip-path, no mask, etc. Otherwise it keeps a `transform` attribute, and the clip, being in user space, follows the item. `SPItem::adjust_clip(postmul)` (:1462) multiplies the clip children's transforms. SPGroup has no `set_transform`, so groups always keep a transform attribute. Consequence for the design: a transform written on the FRAME group moves container, contents and clip together. A transform written on the CONTENTS group moves contents and clip but not the container (misalignment). A transform on the CONTAINER alone moves the live clip (`use`) with it, which is correct.

Design decisions (planner):
- Document structure (one frame = one SVG group; all ids generated by Inkscape):
  ```
  <g inkscape:powerclip="frame" [transform=...]>          ← the PowerClip object, selected/moved as one
    <path|rect|text|g ... inkscape:powerclip="container"/> ← the frame shape, visible (fill + stroke), own transform kept
    <g inkscape:powerclip="contents" clip-path="url(#K)">  ← the contents, identity transform (invariant)
      ...content items, transforms rewritten to keep their visual position...
    </g>
  </g>
  <defs><clipPath id="K"><use xlink:href="#<container id>" x="0" y="0"/></clipPath></defs>
  ```
  Why this parent model, from the evidence: (1) contents follow the container because all three live under the frame group, and a transform on the frame never touches the children (groups keep their transform attribute). (2) The clip is live: reshaping or moving the container moves the clip via the `use`, so the "container = clip shape" invariant holds without code. (3) Clip on a wrapper with a clone of the container (upstream setClipGroup style) would also clip the container's own stroke, while the separate contents group keeps the container's fill and stroke intact. (4) Clip ON the container is impossible, since the container would clip itself and has no children. Rejected: duplicating container geometry into the clip, which would not be live.
  Stacking: container under contents. Contents paint over the container's fill and over the inner half of its stroke. CorelDRAW paints the frame outline above the contents. That needs a second paint of the container, which is not possible without a display change (SVG `use` cannot override the referenced element's own fill). It is recorded as a known difference and design note, not done.
- Gtk-free model `src/object/powerclip.{h,cpp}`, `namespace Inkscape::PowerClip`. Includes only object/document/xml/2geom/ObjectSet headers, no ui/ and no desktop. Forward-declare SPDesktop nowhere.
  - `inline constexpr char const *attr = "inkscape:powerclip";` with role values `"frame"`, `"container"`, `"contents"`.
  - Queries (const, null-safe): `bool is_frame(SPObject const *)` (an SPGroup with attr == frame), `SPGroup *frame_of(SPObject *)` (nearest ancestor-or-self frame, nullptr if none), `SPItem *container_of(SPGroup *frame)` (first direct SPItem child with role container), `SPGroup *contents_of(SPGroup *frame)` (first direct SPGroup child with role contents), `std::vector<SPItem*> content_items(SPGroup *frame)`, `std::vector<SPGroup*> frames(SPDocument *)` (document order, all depths incl. master layers and frames nested inside contents).
  - `enum class Refusal { None, TooFewItems, NoContainer, ContainerIsLayer, ContentIsLayer, ContainerInsideContent, ContentContainsContainer, NoContents, NotInFrame };` + `char const *refusal_message(Refusal)` (untranslated stable text for the CLI/log; the action shows a translated flash).
  - `struct PlaceResult { SPGroup *frame = nullptr; Refusal refusal = Refusal::None; };`
    `PlaceResult place_inside(ObjectSet &set);` Rules, in order:
    1. `set.size() < 2` → TooFewItems.
    2. The target is `set.lastItem()` (Corel picks the frame last, and 04-04 uses "last selected = active object" for align). If the target is a frame, or the container/contents of a frame, then `frame_of`/container decides, and the target frame is reused (add-to-frame). A target that is a layer → ContainerIsLayer.
    3. Contents = every other selected item, minus the target frame itself and anything already inside its contents. Any layer among them → ContentIsLayer. The target is a descendant of a content → ContainerInsideContent. A content is an ancestor of the target → ContentContainsContainer. Empty after filtering → NoContents.
    4. `doc->ensureUpToDate()`. Record each content's `i2doc_affine()`.
    5. New frame (not add-to-frame): create `svg:g` with role frame at the container's position in the container's parent (`addChild(frame, container_repr)` ordering so z-order is preserved). MOVE (not duplicate) the container repr into it, which keeps its id, transform and every reference to it (clones, textPath, the clip use). Set role container. Create the contents `svg:g` (role contents) after it. Ensure the container has an id (`getId()`/repr `id`). Create the clip with `SPClipPath::create({use})`, where `use` = `svg:use` `xlink:href="#<container id>"` `x=0 y=0`, and set `clip-path="url(#K)"` on contents.
    6. Move each content repr (document z-order, sorted with `sp_object_compare_position_bool`) to the END of the contents group, again keeping its id (GC-anchored remove + append; probe `Inkscape::GC::anchor`/`sp_repr_unparent` + `appendChild` idiom). Then `doWriteTransform(old_i2doc * contents->i2doc_affine().inverse())` so the visual position on the page is unchanged. Contents that are clones of each other move like any item; ids are kept, so no relinking is needed.
    7. `set.set(frame)`. Return the frame.
    The model does NOT record undo. The action calls `DocumentUndo::done` once, so the gtest can assert "one undo step reverts byte-identically".
  - `std::vector<SPItem*> extract(ObjectSet &set);` For every distinct `frame_of(item)` of the selection (frames sorted in document order, innermost first if nested selections overlap): move each content child (in order) out to the frame's parent directly above the frame, rewriting transforms to keep `i2doc` (same formula with the parent's i2doc). Move the container to the frame's position with transform `frame.transform * container.transform` (i2doc-preserving formula, so it also works for any frame transform), and remove its role attribute. Remove `clip-path` from contents, delete the clipPath if `!isReferenced()`, delete the contents group and the frame. Select the extracted content items (Corel selects the extracted contents). Return them. A selection with no frame returns empty (the action flashes NotInFrame).
  - `bool normalize(SPGroup *frame);` Repairs the two invariants and returns true if it changed anything:
    (a) contents group transform not identity → push it into each content child (i2doc-preserving rewrite) and clear the contents transform, so the live clip and the container line up again;
    (b) the contents clip must be a clipPath with exactly one `svg:use` child whose href is `#<own container id>` and must not be shared (`hrefcount` 1, or no other frame's contents references it; probe the SPObject reference counter, `hrefcount`/`isReferenced`). Otherwise create a fresh clip for this frame, point contents at it, and delete the old clip if unreferenced. This fixes duplicated frames before their container is reshaped (see context), and also a contents group whose clip was released by an upstream command.
    A frame missing its container or contents group is left untouched (returns false) and logged with g_warning. The structure is not guessed.
  - Edit/finish targets (pure, no desktop): `SPGroup *edit_target(SPObject *selected)` = `contents_of(frame_of(selected))` (nullptr when not in a frame) and `SPGroup *finish_target(SPObject *current_layer)` = the frame whose contents group is `current_layer` or an ancestor of it (nullptr otherwise). Groups entered INSIDE the contents still finish to the frame.
  - Lock/unlock contents (Corel "Lock contents to PowerClip" off), empty frames (Corel keeps an empty frame after extract), content-centred placement (Corel's optional auto-centre) and nested PowerClip UI are NOT in scope. Contents are always locked, extract always dissolves the frame, and placement always keeps absolute positions. Nested frames work structurally (a frame can be content of another) and the gtest covers it.
- Actions `src/actions/actions-powerclip.{h,cpp}` (`void add_actions_powerclip(InkscapeApplication *app);`), all `app.` (headless-safe, act on `app->get_active_selection()`):
  - `app.object-powerclip-place` "Place Inside Frame": run place_inside. On refusal, show the translated message (flash on the desktop message stack if there is a desktop, `show_output`/g_warning otherwise, following actions-master-layer.cpp) and do not create an undo step. On success, `DocumentUndo::done(doc, RC_("Undo", "Place inside PowerClip"), "")`.
  - `app.object-powerclip-extract` "Extract Contents": run extract → `DocumentUndo::done(..., RC_("Undo", "Extract PowerClip contents"), "")`. NotInFrame → message, no undo step.
  - `app.object-powerclip-edit` "Edit Contents": needs `app->get_active_desktop()`. Without one, print "object-powerclip-edit: needs a window" (warning, no-op). Target = `edit_target(selection->single())`. If `normalize(frame)` changed anything → `DocumentUndo::done(..., RC_("Undo", "Repair PowerClip"), "")`. Then `desktop->layerManager().setCurrentLayer(contents)` and select the content items. The upstream TranslucencyGroups does the dimming.
  - `app.object-powerclip-finish` "Finish Editing": needs a desktop. Target = `finish_target(layerManager().currentLayer())`. Run normalize (+ the repair undo step if changed). Then `setCurrentLayer(frame->parent)` (its layer/group) and `selection->set(frame)`. Without a target → message, no-op.
  - `app.object-powerclip-list` "List PowerClips": print one stdout line per frame in document order, `powerclip <frame-id> container=<container-id> contents=<id>,<id>,... clip=<clipPath-id> use=<href-id>`, then `powerclip-count <n>`. This is the CLI model oracle, like `layer-master-list`.
