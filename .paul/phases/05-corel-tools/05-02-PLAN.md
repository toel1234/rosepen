<objective>
Give Rosepen CorelDRAW's dimension tools: persistent dimension objects that measure the distance (parallel/aligned, horizontal, vertical), a path segment, or an angle, show a text label with value and unit, and LIVE-UPDATE when the measured objects move, resize or are node-edited. Precision, units, offset, label position and Corel-like styling (hairline, filled arrowheads, extension lines with gap/overshoot, label above the line) are configurable per dimension and as tool defaults.

Purpose: Phase 5 adds Corel-only tools. Upstream (pinned 3d6e954a) only has (a) the Measure tool, which reports on canvas and can "mark dimension" as STATIC paths/text (no link back to the geometry), and (b) the Measure Segments LPE, which annotates the segments of the path it sits on, puts its satellites at the document root and injects a global `<style>`. Neither gives Corel's "dimension attached to two objects" semantics. This plan adds a small new LPE that IS the live link (built on the upstream SatelliteParam listening machinery), a pure, gtest-locked geometry/label model, CLI-reachable actions (the single source of truth, also used by the tool), and a Dimension tool in the 04-01 dimension flyout.

Output: `dimension-geometry` model (gtest), `LPEDimension` + `app.dimension-add|list|set` (gtest document fixture + headless CLI corpus with SVG/PNG[/PDF] stages, including a live-move scenario), the interactive Dimension tool with property-bar toolbar, flyout/menu wiring, and a manual UAT for the interactive parts.
</objective>

Design decisions (planner, from the evidence above):
- WRAP-IN-NEW-LPE, not a new SP object and not measure-segments. A new SPDimension would need src/object + factory + renderer + export work (src/object is 05-01's area) and would be invisible in other SVG viewers. Measure Segments measures its own path and scatters satellites at the root. A new LPE gets live updates for free from SatelliteParam, outputs a plain svg:path (exports to PNG/PDF/PDF-X with zero pipeline change), and persists its parameters in `inkscape:path-effect` defs.
- Dimension object = a group: `<g class="rosepen-dimension" inkscape:label="Dimension">` containing (1) `<path class="rosepen-dimension-line">` with the `dimension` LPE (output = extension lines + dimension line/arc + arrowheads) and (2) `<text class="rosepen-dimension-label">` (one tspan). The LPE finds its label STRUCTURALLY (first sibling svg:text with that class in the same parent) — no id references, so duplicate/copy/paste of a dimension never cross-wires labels. Style: path `fill:#000;stroke:#000;stroke-width:0.2mm-equivalent`; arrowheads are closed filled triangles; every open subpath is emitted so it encloses zero area (straight lines naturally; the angular arc as arc + reversed arc), so one fill+stroke style renders Corel-style filled arrows without markers. Label: `font-size` from param, `text-anchor:middle`, fill = line color at creation; user restyling of either child is kept (the LPE only rewrites label content, x/y and transform).
- LPE parameters (key `dimension`, label "Dimension", icon `measure-segments`, category Convert, on_path true, on_shape false, on_group false, experimental TRUE — hidden from the default gallery because the supported entry points are the tool and `app.dimension-add`): `kind` enum {aligned, horizontal, vertical, angular, segment}; `start_ref`, `end_ref`, `vertex_ref` SatelliteParam; `start_anchor`, `end_anchor`, `vertex_anchor` TextParam; `offset` (mm, default 5; for angular = arc radius, ≤0 → half the shorter arm); `precision` (0..6, default 2); `unit` UnitParam (default mm); `scale` (drawing scale factor, default 1); `text_position` enum {above, inline, below} (default above); `text_horizontal` bool (default false = parallel to line, upright-normalised like Measure tool); `show_units` bool (default true); `prefix`, `suffix` TextParam; `font_size` (pt, default 10); `arrow_length` (mm, 2.5); `ext_gap` (mm, 1); `ext_overshoot` (mm, 2); hidden `last_points` TextParam (freeze state, not shown in the widget).
- Anchor grammar (shared by LPE params, actions and tool): `bbox:<tl|t|tr|l|c|r|bl|b|br>` (document GEOMETRIC bbox), `node:<k>` (k-th node of the item's curve in document coords: each subpath's start point then every segment end point, the closing segment's end of a closed subpath not counted twice), `rel:<u>/<v>` (fraction of the geometric bbox, follows move AND scale). An empty ref = free point taken from the LPE path's own `inkscape:original-d` nodes (start = first node, end = last; angular: arm A, vertex, arm B = nodes 0,1,2), so free points move with the dimension.
- Kinds (all in document coords; values in `unit` after doc scale × `scale`): aligned/segment = |P2−P1|, line parallel to P1P2 offset to the LEFT of P1→P2 by `offset` (negative flips side); horizontal = |x2−x1|, line at y = min(y1,y2) − offset (doc y-down; negative → max + |offset|); vertical = |y2−y1|, line at x = max(x1,x2) + offset (negative → min − |offset|); angular = angle between V→A and V→B in degrees (0, 180], arc of radius `offset` centred at V, label "°" at the arc midpoint outside the arc. `segment` = aligned between `node:k` and `node:k+1` of ONE item (closed subpath: last k wraps to the subpath start); chord length (Corel segment dimension semantics; curve-length dims deferred). `auto` exists only at creation time (action/tool): horizontal if |dx| ≥ |dy| else vertical, stored as the concrete kind.
- Label = `{prefix}{value}{sep}{unit}{suffix}`, value via `format_classic(std::fixed, setprecision(precision))` (locale-independent, '.' decimal), `sep` = " " for linear units, "" for "°"; units omitted when `show_units` is false. Corel default look: "50.00 mm".
- Live-update and freeze: a missing/deleted/invalid ref (or an anchor that cannot resolve, e.g. `node:99`) falls back to the LAST resolved points stored in `last_points` (written by the LPE only when the resolved points change by > 1e-6 uu, guarded against re-entry, inside `DocumentUndo::ScopedInsensitive`), and only if empty to the original-d nodes. So deleting a measured object FREEZES the dimension at its last value (Corel behaviour) and never crashes or collapses it. Moving the dimension GROUP itself: free dims move with it; linked dims stay glued to the measured geometry in document coords (output computed via the path's `i2doc_affine().inverse()`); if the LPE is not re-evaluated on an ancestor transform, the LPE connects the group's transformed signal to `requestModified` (gtest-locked either way).
- Creation parent: GUI tool → current layer; action without desktop → parent of the first referenced item (same layer/page; master layers work unchanged), else the document root.
- Interactive tool `Dimension` (pref path `/tools/dimension`, cursor `measure.svg`, icon `measure-segments`): mode buttons on its property-bar toolbar {Auto (horizontal/vertical by drag), Parallel, Angular, Segment}; points snap via the desktop SnapManager; anchor capture = `node:k` if the snapped/picked point is within tolerance of a node of the item under it, `bbox:<9-point>` if within tolerance of a bbox handle, `rel:u/v` if inside the item's bbox, else a free point. Flow: press P1 → drag/release P2 (Segment: one click on a segment) → move to set the offset (Angular: vertex, arm A, arm B, then radius) → click commits through the SAME `DimensionOps::create` as the action. Esc cancels. Preview uses temporary canvas items, not document objects. Toolbar edits (precision, unit, text position, show units) set `/tools/dimension/*` defaults AND apply to selected dimensions via `DimensionOps::set` (Corel property-bar semantics). Toolbox: `[group:dimension] tools=Dimension;Measure;Connector` (Dimension becomes the face, as Corel's dimension flyout). No default key (CorelDRAW has none).
