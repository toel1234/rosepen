# PLAN 02-01: Document CMYK core

<objective>
Make a Penrose document CMYK-native through the existing Colors:: system. Add a single "output profile" concept to DocumentCMS: one attached CMYK `<color-profile>`, chosen per document. Add an action that converts selected fill/stroke flat colors into that profile as `icc-color(...)` values. Show the document's ICC spaces as editable channel pages in Fill&Stroke. Let a preference attach a default CMYK profile to new documents. Cover the core with gtests.
EXTEND Colors::. Do not add a parallel color system.
</objective>

<acceptance_criteria>
AC-1 (output profile model)
  Given a document with `default_cmyk.icc` attached as `<color-profile name="cmyk-out">`
  When `DocumentCMS::setOutputProfile("cmyk-out")` is called
  Then `getOutputSpace()` returns that Space::CMS with `getComponentType() == Space::Type::CMYK`
  And the namedview repr carries `inkscape:output-profile="cmyk-out"`
  And after save to a temp file and reload, `getOutputSpace()->getName() == "cmyk-out"`.
  If the attribute is unset, getOutputSpace() falls back to the first attached space whose component type is CMYK, or nullptr if there is none. Setting the output profile to a name that is not CMYK returns false and changes nothing.

AC-2 (convert to output profile, serialization round-trip)
  Given that document and a rect with `fill:#ff0000;stroke:cmyk(0,0,0,1)` (DeviceCMYK)
  When `DocumentCMS::convertToOutputSpace(color)` is applied to fill and stroke, either directly in the test or through the action `app.object-convert-to-output-profile`
  Then each value matches `^#[0-9a-f]{6} icc-color\(cmyk-out, [0-9.]+, [0-9.]+, [0-9.]+, [0-9.]+\)$`
  And after save and reload the `icc-color(...)` substring is byte-identical
  And colors already in the output space are left unchanged (idempotent: converting twice gives the same string).

AC-3 (new-document default)
  Given preference `/options/document/outputprofile/uri` = absolute path to `default_cmyk.icc`
  When `InkscapeApplication::document_new()` creates a document
  Then that profile is attached (HREF_FILE storage) and is that document's output profile.
  With the preference empty (the default), new documents have no `<color-profile>` and no `inkscape:output-profile`. Default behaviour is unchanged.

AC-4 (Fill&Stroke CMYK editing)
  Given a desktop document whose output profile is CMYK
  When the Fill&Stroke ColorNotebook is shown
  Then it has a page named after the profile's space with 4 channel sliders, and editing writes `icc-color(<profile>, c, m, y, k)` (code path: ColorPage on a Space::CMS from `getSpaces()`)
  And the page is added or removed when profiles are linked or unlinked (`connectChanged`) and when the document is replaced.
  This is machine-checked indirectly: build passes, plus the unit test from AC-2 on the same Space::CMS toString path. It is also covered by a reviewer read-through of the color-notebook.cpp diff.

AC-5 (tests and regressions)
  `ninja -C build test_colors_document-output-profile test_colors_document-cms colors-spaces-cmyk-test colors-spaces-cms-test colors-color-test` succeeds
  And `ctest --test-dir build -R '^(test_colors_document-output-profile|test_colors_document-cms|colors-spaces-cmyk-test|colors-spaces-cms-test|colors-color-test)$' --output-on-failure` reports 100% pass
  And `fork/scripts/verify-branding.sh` exits 0.
</acceptance_criteria>

  <name>DocumentCMS output-profile API + conversion core</name>
  <files>src/colors/document-cms.h, src/colors/document-cms.cpp</files>
  <action>
  Add these public members to DocumentCMS. Follow the existing style: std::shared_ptr<Space::CMS> returns and std::optional<Color>.
  - `std::shared_ptr<Space::CMS> getOutputSpace() const;` It reads `inkscape:output-profile` from `_document->getNamedView()->getRepr()`. Use the raw repr attribute; do NOT add a new SPAttr enum entry. It resolves the value with `getSpace(name)`. If the attribute is missing or does not resolve, it falls back to the first element of `getSpaces()` whose `getComponentType() == Space::Type::CMYK`, and otherwise returns nullptr.
  - `bool setOutputProfile(std::string const &name);` It requires `getSpace(name)` to be CMYK. If so, it sets the repr attribute and emits `_changed_signal`. Otherwise it returns false. An empty name removes the attribute.
  - `std::optional<Color> convertToOutputSpace(Color const &color) const;` If there is no output space, return {}. If `color.getSpace()` is already the output space, return the color unchanged. Otherwise return `color.converted(outputSpace)`. Alpha handling stays whatever Color::converted does today; opacity policy is decided in 02-02.
  Include headers only as needed: object/sp-namedview.h and xml/node.h in the .cpp only. Leave the existing attach/remove behavior untouched. In `removeProfile`, if the removed space is the current output profile, clear the attribute.
  </action>
  <verify>fork/scripts/build-local.sh  (must finish without errors; ~5 min warm)</verify>
  <done>The API compiles. No behavior change for documents without the attribute.</done>
</task>
